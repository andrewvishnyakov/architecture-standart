| Код | Требования                         | Комментарий  |
|-----|------------------------------------|--------------|
| F   | Функциональные (Functionality)     |              |
| F1 | Сайт показывает список депозитов с актуальными ставками |  |
| F2 | На сайте новый клиент может подать заявку на депозит (ФИО, телефон) | |
| F3 | Интернет-банк показывает список доступных депозитов и персонализированные ставки клиента |  |
| F4 | Клиент интернет-банка может оформить заявку на открытие депозита, указав счёт и сумму |  |
| F5 | Подтверждение заявки в интернет-банке выполняется по СМС-коду | |
| F6 | Менеджер бэк-офиса депозитов обрабатывает заявки и подтверждает условия депозита в АБС | |
| F7 | Клиент получает СМС-уведомление о подтверждении ставки и об открытии депозита |  |
| F8 | Сотрудники бэк-офиса депозитов и кредитов работают со ставками в одной системе | вместо XLS-файлов |
| F9 | Возможность назначения специальных ставок по клиенту |  |

| U   | Удобство использования (Usability) |              |
| U1 | Система дизайна, принятая в компании | Сайт и интернет-банк используют брендированные цвета, шрифты и т.д. |
| U2 | Быстрый отклик интерфейса для всех операций | пользователь не должен ощущать задержек|
| U3 | Статус заявки на депозит для клиента | клиент понимает, на каком этапе заявка (принята, в обработке и т.д |

| R   | Надёжность (Reliability)           |              |
| R1 | Доступность интернет-банка и новых сервисов не ниже 99,9% |  |
| R2 | Работа сервисов 24/7 | Обслуживание проводить в часы минимальной предполагаемой нагрузки |
| R3 | Минимизация влияния подачи онлайн-заявок на производительность АБС | применение промежуточного сервиса и очередей. |
| R4 | 100% обработка заявок | При сбоях в сетях или сервисах заявки не теряются, а доходят после восстановления. |

| P   | Производительность (Performance)   |              |
| P1 | Время отклика операций — миллисекунды | Основные действия должны выполняться визуально мгновенно |
| P2 | Время загрузки справочных данных < 1 секунды |  |
| P3 | Горизонтальное масштабирование интернет-банка и сайта | добавлять экземпляры приложений и распределять нагрузку между серверами и ЦОД. |
| P4 | Управляемая нагрузка на АБС | так как БД системы уже перегружена|

| S   | Поддерживаемость (Supportability)  |              |
| S1 | Использование стека, уже имеющегося в банке (MS SQL, Oracle, .NET, Java, ...) | Снижает риски внедрения и сопровождения силами текущих команд |
| S2 | Возможность перевода интернет-банка на микросервисную архитектуру | Начать с модуля для депозитов, потом тиражировать решение. |
| S3 | Разработка документаиции | API и др. для дальнейшего расширения системы |
| S4 | Автоматическое тестирование | Модульное, интеграционное. Для безопасного вносения изменений в нескольких системах. |


| +R  | + Ограничения (Restrictions)       |              |
| +R1 | Прямая работа интернет-банка с API АБС в новом процессе должна быть исключена | БД АБС перегружена и масштабируется только вертикально |
| +R2 | Использование механизмов шифрования трафика для сайта и интернет-банка | передаются чувствительные данные клиентов. |
| +R3 | Максимальное использование уже имеющихся технологий |  |
